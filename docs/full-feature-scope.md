# 8자어때 전체 기능 구현 범위

## 완료 여부
**전체 구현은 완료되지 않았다.** 지금까지의 완료 표시는 일부 화면/코드/개발환경 테스트에 한정된다.
사용자의 요구는 “특정 스크린샷 몇 장”이 아니라 **개인용 앱으로 사용할 전체 기능과 UI·UX**다.

원본 18.2.8의 `libapp.so`를 REA 6.4.0으로 다시 검사했고, 별도 문자열 검사로 `package:how8ja/` 경로 1,015개와 `features` 하위 27개 영역을 분류했다.
이것은 함수 본문이나 런타임 메뉴의 완전 복원 증거가 아니다. 해당 단서와 현재 코드를 대조해 아래 **79개 작업 단위**를 만들었다. “원본 앱의 기능이 정확히 79개”라는 뜻은 아니다.

## 이어서 구현: 간지 입력과 역검색
- **간지 직접 입력**: 시·일·월·연주, 시주 미상, 저장/수정/해석/백업. 실제 날짜를 만들지 않으며 생일 없이 나이·대운 시작일을 계산하지 않는다. 원본의 커스텀 대운수 입력 옵션이 남아 있어 이 작업은 일부 구현으로 유지한다.
- **네 기둥 역검색**: 1900~2030년 중 연·월·일·시주가 동시에 일치하는 후보 날짜와 시간 구간. 시주 미지정, 취소, 오래된 결과 제거, 한도 안내. 실제 출생시각을 자동 확정하지 않고 날짜만 입력 화면으로 전달한다.
- **미상 시각 후보 비교**: 00:00~23:59를 빠짐없이 13개 구간으로 나누고 두 후보를 비교. 선택은 조회일 뿐 기존 출생정보를 변경하지 않는다.
- **중복 확인**: 일반/간지 입력 모두 같은 이름·같은 입력의 경고, 취소, 별개 저장. 확인했던 중복 명식의 메모만 수정할 때는 재경고하지 않는다.
- 기존 `src/App.jsx`와 Android Java/SQLite 코드는 변경하지 않았다. 날짜 기반 명식의 이전 107개 테스트를 모두 유지하고 전체 테스트 140개를 통과했다.
- 19개 브라우저 점검: 간지 입력·수정·재열기, 역검색·취소·조건 변경, 후보 날짜 이동, 후보 비교, 중복 처리, 오프라인 조작, UI 백업/빈 저장소 복원. 320/360/390/800px의 신규 화면 가로 넘침과 페이지·콘솔 오류, 외부 요청은 0이다.
- 검증 브라우저: Playwright 1.51.1 / Chromium. 브라우저 플러그인이 없어 기존 도구 사용. 오프라인 검증은 첫 로드 후 네트워크 차단이며 Android 실기기·APK 업데이트 검증은 아니다.
- 원본 입력/역검색 화면의 픽셀 동일성, 원본 산식과의 동일성, 정밀 절입·시간 보정은 미검증이다. **원본 동등성 완료 항목은 늘리지 않았다.**

## 앞선 변경
- **그룹 관리**: 생성·이름 수정·복수 그룹 배정·멤버 검색·필터·미분류·소프트 삭제·복원. 그룹 삭제는 명식을 지우지 않는다.
- **보기 설정 저장**: 정렬·조밀한 목록·한자·큰 운 목록·선택운 설정을 명식 저장소에 보관하고 JSON 백업/복원에 포함한다.
- **만세력 도구**: 월별 일주 달력, 12개 대표 시주, 날짜를 선택하여 신규 입력, 일주로 날짜 검색·취소·결과 한도 표시, 십성·지장간·운성 조견표.
- **UI 회귀 수정**: 이전 상세 컴포넌트 교체 때 빠진 밝은 팔레트 CSS 연결을 복구하여 입력·설정·그룹·도구 화면의 어두운 배경을 수정했다.
- `src/App.jsx` 및 Android Java/SQLite 클래스는 변경하지 않았다. 명식의 생년월일·수정 이력·원본은 UI 설정과 분리한다.

## 아직 해결하지 않은 핵심
가중치 편집, 정확한 절입/역사적 시각 보정, 모든 격국·용신·신살, 일·시운 분석, 궁합 점수/튜닝, 커스텀 대운수 옵션, 유사 명식, 다중 메모/사진/그림, 전체 표시 옵션과 공유 범위는 미완료다.
`커스텀`은 이제 간지 직접 입력을 열며, 목록 간격 설정은 설정 화면으로 옮겼다. 비중 버튼이 설명만 여는 것도 가중치 기능의 구현으로 계산하지 않는다.

## 구현 완료 판정
입력 → 조작 → 실제 결과 → 필요한 저장/재열기 → 오프라인 → 회귀 검증을 모두 통과해야 작동 구현으로 본다.
원본 앱의 결과/화면/조작과 대조하기 전에는 **원본 동등성 검증 완료**로 올리지 않는다. 미연결을 0점이나 가짜 설명으로 대신하지 않는다.

```sh
node scripts/check-full-feature-scope.mjs
node scripts/check-full-feature-scope.mjs --require-complete
```
두 번째 명령은 미완료가 남아 있는 동안 실패하는 것이 정상이다. 빌드/테스트 성공과 제품 전체 완료를 분리한다.

## 서버 의존 영역 처리
로그인·계정 서버, 광고 SDK·결제, 푸시·피드백·공지 원격 서버는 개인 오프라인 앱에 그대로 연결하지 않는다.
그 뒤의 사용자 기능은 삭제하지 않고 자체 기능/로컬 백업/자료 가져오기 등 대안을 검토한다. 공개 인물 명식은 검증된 데이터 공급/갱신 방안이 필요하다. 원본의 접근 제어나 유료 API를 우회하지 않는다.

## 저장 호환성
기존 v1 스냅샷은 그대로 읽는다. 그룹/보기 설정을 처음 저장하면 검증된 선택적 `workspace` 네임스페이스가 추가된다.
확장된 새 백업은 이를 모르는 구버전 앱으로 가져오지 않는다. 기존 상태를 덮어쓰기 전에 사이즈와 버전을 검사한다.
백업 병합 시 현재 그룹·구성원·설정·삭제 표식을 우선 보존하여 오래된 백업이 삭제 그룹을 되살리거나 설정을 덮지 않게 한다.

## 이번 검증
- JavaScript **107개 통과**: 기존 83 + 그룹/설정 18 + 날짜 도구 6.
- 모바일 및 기존 웹 프로덕션 빌드 성공.
- Playwright 1.51.1/Chromium: 생성→분류→편집→삭제→복원, 재열기, 달력→입력, 역검색 정상/오류, UI 파일 내보내기→빈 저장소 복원 등 **17개 브라우저 점검** 통과.
- 달력 320/360/390/800px: 문서 가로 넘침 없음. 해당 신규 화면의 원본 픽셀 동등성 검증은 아님.
- 페이지·콘솔 오류 및 외부 요청 0. 브라우저 플러그인이 없어 기존 Playwright 도구 사용.
- 오프라인은 최초 로드 후 네트워크 차단 조작 검증. Android 실기기/업데이트/시스템 파일 선택기와 신규 APK 서명 검증은 이번 단계에서 수행하지 않았다.
